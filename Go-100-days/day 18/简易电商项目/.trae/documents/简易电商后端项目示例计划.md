# 简易电商后端项目示例 - 实施计划

## 一、项目概述

为 Go 初学者定制的电商后端示例项目，技术栈：**Gin + GORM + MySQL + Redis + Viper + Docker**。

**目标**：帮助"看得懂但写不出来"的学习者，通过一个结构清晰、注释详尽的项目，掌握从零独立开发的能力。

**设计原则**：
1. **分层清晰**：controller → service → dao → model，每层职责单一，便于模仿
2. **注释详尽**：每个文件、每个关键步骤都有中文注释，说明"为什么这么写"而非仅"这是什么"
3. **循序渐进**：按模块拆分，每个模块可独立运行验证，避免一次性面对过多代码
4. **精简够用**：只包含电商核心功能，不引入 elasticsearch/rabbitmq 等额外复杂度

## 二、GitHub 调研结论

搜索了约 50 个 Go 电商项目，结论：
- 多数高星项目为**微服务架构**（go-zero/Hertz/Kitex/gRPC），对初学者过于复杂
- 单体项目中多数使用 PostgreSQL 而非 MySQL
- **无完全匹配技术栈且对初学者友好的项目**，故从零定制

可参考项目（供后续深入学习）：
- `alireza-fa/golang-car-shop`（gin+gorm+viper+redis+docker，Clean 架构参考）
- `blazeout/killShopping`（gin+gorm+JWT 异步下单思路）
- `JunLang-7/mall`（极简 gin+gorm 商城）

## 三、功能模块（精简核心版）

| 模块 | 功能点 | 学习重点 |
|------|--------|----------|
| 用户 | 注册、登录、JWT鉴权 | 密码加密、JWT 签发与验证、中间件 |
| 商品 | 增删改查、分页列表 | RESTful API、GORM CRUD、分页 |
| 购物车 | 加购、查看、修改数量、删除 | 用户关联数据、Redis 缓存购物车 |
| 订单 | 创建订单（从购物车结算）、查看列表 | 事务处理、多表关联、库存扣减 |

## 五、具体实施步骤

### 步骤 1：项目初始化与配置

**文件**：
- `go.mod` — 模块定义（module 名 `simple-ecommerce`，Go 1.21）
- `config/config.yaml` — 数据库/redis/jwt 配置
- `pkg/config/config.go` — Viper 加载配置到结构体

**要点**：
- config.yaml 包含 mysql（host/port/user/password/dbname）、redis（addr/password/db）、jwt（secret/expire）三组配置
- Viper 读取 yaml 并反序列化到全局 Config 结构体，使用 `viper.Unmarshal`
- 注释说明每个配置项的作用

### 步骤 2：基础设施初始化

**文件**：
- `initialize/mysql.go` — GORM 连接 MySQL，开启日志模式便于调试
- `initialize/redis.go` — go-redis v9 连接 Redis
- `pkg/response/response.go` — 统一 JSON 响应格式 `{code, msg, data}`

**要点**：
- MySQL 用 `gorm.Open` + `gorm.Config{Logger: ...}`，注释每行参数含义
- Redis 用 `redis.NewClient`，测试 ping 连通性
- response 包提供 `Success(c, data)` 和 `Error(c, msg)` 两个快捷函数

### 步骤 3：用户模块

**文件**：
- `internal/model/user.go` — User 模型（ID, Username, Password, Phone, CreatedAt）
- `internal/dao/user.go` — 用户数据操作（CreateUser, GetUserByUsername）
- `internal/service/user.go` — 注册（密码 bcrypt 加密）、登录（校验+签发 JWT）
- `internal/controller/user.go` — 注册/登录接口，参数绑定与校验
- `pkg/jwt/jwt.go` — JWT 生成与解析工具
- `internal/middleware/jwt.go` — 鉴权中间件，从 Header 提取 token 验证

**要点**：
- 密码用 `golang.org/x/crypto/bcrypt` 加密，注释说明为何不用 md5
- JWT 用 `github.com/golang-jwt/jwt/v5`，Claims 存用户 ID 和用户名
- 中间件验证通过后将用户信息存入 `c.Set("user_id", ...)` 供后续使用
- controller 用 `c.ShouldBindJSON` 绑定参数，加 `binding:"required"` 标签校验

### 步骤 4：商品模块

**文件**：
- `internal/model/product.go` — Product 模型（ID, Name, Price, Stock, Description, ImageURL, CreatedAt）
- `internal/dao/product.go` — 商品 CRUD + 分页查询
- `internal/service/product.go` — 业务逻辑（创建、更新、删除、列表分页）
- `internal/controller/product.go` — RESTful 接口

**接口设计**：
- `POST   /api/v1/products`        创建商品（需管理员，此处简化为需登录）
- `GET    /api/v1/products`        商品列表（分页 ?page=1&size=10）
- `GET    /api/v1/products/:id`    商品详情
- `PUT    /api/v1/products/:id`    更新商品
- `DELETE /api/v1/products/:id`    删除商品

**要点**：
- 分页用 GORM 的 `Offset` 和 `Limit`，注释分页计算公式
- 路径参数用 `c.Param("id")`，查询参数用 `c.Query("page")`
- 统一用 response 包返回，错误处理清晰

### 步骤 5：购物车模块（Redis 实践）

**文件**：
- `internal/model/cart.go` — CartItem 结构（ProductID, Quantity，存 Redis 用）
- `internal/dao/cart.go` — Redis 操作（HSet/HGet/HDel/HGetAll）
- `internal/service/cart.go` — 加购、查看、修改、删除逻辑
- `internal/controller/cart.go` — 购物车接口

**接口设计**：
- `POST   /api/v1/cart`            加入购物车
- `GET    /api/v1/cart`            查看购物车
- `PUT    /api/v1/cart/:product_id` 修改数量
- `DELETE /api/v1/cart/:product_id` 移除商品

**要点**：
- 购物车用 Redis Hash 存储，key 为 `cart:{user_id}`，field 为 product_id，value 为数量
- 注释说明为何购物车用 Redis 而非 MySQL（高频读写、临时性）
- 查看购物车时从 Redis 读 product_id 列表，再批量查 MySQL 商品详情

### 步骤 6：订单模块（事务实践）

**文件**：
- `internal/model/order.go` — Order 模型 + OrderItem 模型（一对多）
- `internal/dao/order.go` — 订单数据操作（事务创建订单）
- `internal/service/order.go` — 创建订单（结算购物车）、查询订单
- `internal/controller/order.go` — 订单接口

**接口设计**：
- `POST   /api/v1/orders`          创建订单（从购物车结算）
- `GET    /api/v1/orders`          我的订单列表
- `GET    /api/v1/orders/:id`      订单详情

**要点**：
- 创建订单使用 GORM 事务 `db.Transaction`，注释说明事务必要性（同时写订单+订单项+扣库存+清购物车）
- 订单号用时间戳+随机数生成，注释生成规则
- Order 与 OrderItem 一对多关系，用 `gorm:"foreignKey:OrderID"` 关联

### 步骤 7：路由整合与入口

**文件**：
- `internal/router/router.go` — 注册所有路由，分组（公开组/鉴权组）
- `main.go` — 程序入口（加载配置→初始化DB/Redis→注册路由→启动服务）

**要点**：
- 路由按 v1 版本分组，公开路由（登录注册、商品列表）与鉴权路由（购物车、订单）分离
- main.go 流程清晰：配置 → 初始化 → 路由 → `r.Run()`
- 启动时打印路由列表便于调试

### 步骤 8：Docker 化

**文件**：
- `docker-compose.yml` — 编排 MySQL + Redis + 应用
- `Dockerfile` — 多阶段构建 Go 应用

**要点**：
- docker-compose 包含 mysql 8.0、redis 7、app 三个服务
- app 依赖 mysql 和 redis，用 `depends_on` + `healthcheck` 确保启动顺序
- Dockerfile 多阶段构建：builder 阶段编译，最终镜像只含二进制文件
- 注释每个指令的作用，便于初学者理解

## 七、注释与教学规范

每个文件遵循统一注释模板：
```go
// 文件用途说明（一句话）
// 学习要点：本文件主要演示 xxx 知识点
//
// 为什么这样设计：xxx

package xxx

// Xxx 结构体说明
type Xxx struct {
    // 字段说明 + GORM 标签含义
    ID uint `json:"id" gorm:"primaryKey"` // 主键，自增
}
```

关键业务逻辑处加 `// 学习要点：` 注释，解释设计原因，例如：
- 为何密码要 bcrypt 而非 md5
- 为何购物车用 Redis 而非 MySQL
- 为何创建订单要事务
- 为何 JWT 放 Header 而非 Cookie

## 八、验证步骤

1. **启动基础设施**：`docker-compose up -d mysql redis`，确认容器健康
2. **运行应用**：`go run main.go`，确认无报错、路由打印正常
3. **接口测试**（按顺序）：
   - 注册用户 → 登录获取 token
   - 用 token 创建商品 → 查询商品列表
   - 用 token 加入购物车 → 查看购物车
   - 创建订单 → 查看订单
4. **数据库验证**：连接 MySQL 检查表结构（GORM AutoMigrate 自动建表）
5. **Redis 验证**：`redis-cli HGETALL cart:1` 检查购物车数据

## 九、假设与决策

1. **假设**：用户本地已安装 Go 1.21+ 和 Docker
2. **决策**：商品管理简化为"登录即可操作"，不区分管理员角色（降低初学者理解成本）
3. **决策**：购物车用 Redis Hash 存储，体现 Redis 实践；订单用 MySQL 事务，体现事务实践
4. **决策**：不引入 zap/logrus 等日志库，用 GORM 自带日志 + gin 默认日志，减少依赖
5. **决策**：不引入 Swagger，接口文档在 controller 注释中说明，避免初学者被额外配置困扰
6. **后续扩展路径**（学完本示例后）：可逐步加入 zap 日志 → Swagger 文档 → 限流中间件 → 支付模拟 → 微服务拆分
