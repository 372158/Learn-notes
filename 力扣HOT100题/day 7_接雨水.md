# 42. 接雨水 (Trapping Rain Water)

> 难度:困难 | 分类:双指针
> 来源:[力扣 HOT 100 - Day 7](https://leetcode.cn/problems/trapping-rain-water/description/?envType=study-plan-v2&envId=top-100-liked)
> 状态:🚧 进行中(2026-09-08)

## 题目描述

给定 `n` 个非负整数表示每个宽度为 `1` 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。

 

**示例 1：**

![示意图](https://assets.leetcode.cn/aliyun-lc-upload/uploads/2018/10/22/rainwatertrap.png)

```
输入：height = [0,1,0,2,1,0,1,3,2,1,2,1]
输出：6
解释：上面是由数组 [0,1,0,2,1,0,1,3,2,1,2,1] 表示的高度图，在这种情况下，可以接 6 个单位的雨水（蓝色部分表示雨水）。 
```

**示例 2：**

```
输入：height = [4,2,0,3,2,5]
输出：9
```

 

**提示：**

- `n == height.length`
- `1 <= n <= 2 * 10^4`
- `0 <= height[i] <= 10^5`

## 我的思路

<!-- 先自己想,把想法写在这里;卡住了向老师要提示 -->

**(2026-09-08,学生主导设计)** 核心视角:**按列算水**。

- 每根柱子上方能存的水 `water(i) = min(左边最高, 右边最高) - height[i]`(短板封顶;两端无挡板,存水为 0)—— 学生独立推出 ✓
- 暴力:每个 i 左右各扫一遍找最高 → O(n²),n=2×10⁴ 时约 4×10⁸,贴死 1 秒法则 → 必须 O(n)
- **对撞 + 双记录**(学生 Q3 提出的 mleft/mright 思想 + 老师补角色分工):left/right 对撞,mleft/mright 各自只记录自己半场走过的最高柱。每回合比较两个**记录**(不是柱子、不是下标):谁矮谁封顶 → 结算矮侧,`res += 矮侧记录 - 矮侧柱高`,且**只有被结算的一侧挪动**。指针走过的路记录都记得,无需回扫 → O(n)。

## 我的代码(终版,Go,2026-09-08)

```go
func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}

func trap(height []int) int {
    left, right := 0, len(height)-1
    mleft, mright := 0, 0
    res := 0
    for left < right {
        mleft, mright = max(mleft, height[left]), max(mright, height[right])
        if mleft <= mright {
            res += mleft - height[left] // 左记录矮,左记录封顶,结算左
            left++
        } else {
            res += mright - height[right] // 右记录矮,结算右
            right--
        }
    }
    return res
}
```

**演进记录**(学生三稿 + 老师终审):① 第一版两处 bug——结算写在 if 外(永远结算左)+ `right++` 方向反;② 第二版 else 里下标写错(结算 right 却查 height[left]);③ 第三版忘删第一版残留行(每轮双记账,[4,2,0,3,2,5] 得 18)+ 死代码 min 函数未删;④ 终版删净,两用例验算通过。

**为什么"先更新记录再结算"是负数保护**:结算前先 `mleft = max(mleft, height[left])`,若当前柱是左半场新高,记录先涨上去,水 = 0 而非负数。顺序不能颠倒。

## 复杂度分析

- **时间复杂度:** O(n) —— left/right 合计走 n 步,每步 O(1);对比暴力 O(n²),这是把"每个 i 重新认识两边"变成"账本随走随记"。
- **空间复杂度:** O(1) —— 只有两个指针、两个记录、一个累加器。

## 关键知识点

1. **按列分解**:接雨水不数"水池"数"柱列",每列独立结算 min(左最高,右最高) - height[i]。把整体问题切成逐列子问题,是这题破局的第一步。
2. **双记录 = 活账本**:mleft/mright 让"扫过的历史"变成 O(1) 可查——这是所有"边走边维护最值"题的通用模式(前后缀最大/最小)。
3. **两个不变量的对照**(本套题最珍贵的收获):
   | | Day 5 盛水 | Day 7 接雨水 |
   | --- | --- | --- |
   | 结算与挪动的关系 | 独立的两件事,每轮无条件挪 | 结算者 = 挪动者,谁结算谁走 |
   | 原因 | 淘汰矮板只为收缩区间 | 结算即处理完该柱,处理完才走 |
4. **镜像测试法**:用例和它的镜像(首尾反转)成本为零,却能把两个分支都逼出来——本题 [4,2,0,3,2,5] 恰好全程走 if 分支,单用例验证无效。
5. **验证纪律**:脑内验证必须走完算术;残留行那种 bug,真走一遍回合 1 就现形(res 涨 4 而非 2)。

## 拓展:另外两把刀(选学)

- **DP 预处理**(更好想):先两次扫描造 `leftMax[]`、`rightMax[]` 数组,再一次遍历逐列结算。O(n) 时间但 O(n) 空间——对撞解法就是把这两个数组压成了两个变量。
- **单调栈**(横向算水):按行算而不是按列算,维护一个高度递减的栈,遇到更高柱子时弹栈结算凹槽。O(n),思路不同,值得以后回看。

## 总结

本题四个锚句:

1. **按列算水:每列的水 = min(两侧最高) - 柱高**;
2. **记录是活账本,走过就记账,无需回头扫**;
3. **谁结算谁挪动**(Day 5 恰好相反:记账与挪动独立——两个不变量分开背);
4. **镜像用例逼出全分支,脑内验证要走完算术**。

第一道 hard 通关。困难题的"困难"一半在算法设计(视角转换),另一半在工程纪律(验证方法)——今天两样都练到了。
