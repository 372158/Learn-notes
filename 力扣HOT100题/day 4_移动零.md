# 283. 移动零 (Move Zeroes)

## 题目描述

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时保持非零元素的相对顺序。

**请注意** ，必须在不复制数组的情况下原地对数组进行操作。

 

**示例 1:**

```
输入: nums = [0,1,0,3,12]
输出: [1,3,12,0,0]
```

**示例 2:**

```
输入: nums = [0]
输出: [0]
```

 

**提示**:

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

 

**进阶：**你能尽量减少完成的操作次数吗？

## 本课知识点(2026-09-05)

**1. 双指针 = 两个下标协同走数组**(不是新数据结构,是循环的编排技巧)。**快慢型**:slow 管"边界"(下一个该放的位置),fast 管"扫描";此外还有**对撞型**(一头一尾往中间走——学生当天自创的那种,适合回文/二分)和**滑动窗口**(后面会学)。

**2. 循环不变量**:任何时刻都成立的规矩,本题是"[0,slow) 全非零且保序,[slow,fast) 全是 0"。用途:① 写完自查代码对不对;② 替你省掉多余的 if——不变量保证的事,不用再查。

**3. 复杂度**:O(n) 时间 / O(1) 额外空间。**额外空间 = 新开的数组/表有多大**,与"传入了多少数据"无关。

**4. Go 积累**:if 条件必须是 bool(C 的"非零即真"不适用);`:=` 多变量要配多值;range 拥有循环下标,别在外层声明同名变量(遮蔽);`a, b = b, a` 一行交换;slice 传参共享底层数组 → 函数内改就是原地修改;`for i := range` 只取下标,`for _, v := range` 只要值。

## 我的代码

第三版(通关版,学生独立写出):

```go
func moveZeroes(nums []int) {
    slow := 0
    for fast := range nums {
        if nums[fast] != 0 {
            if nums[slow] == 0 {      // 多余的防御:不变量保证 slow<fast 时这里必是 0
                nums[slow], nums[fast] = nums[fast], nums[slow]
            }
            slow++
        }
    }
}
```

简化版(去掉多余检查,range 直接取值):

```go
func moveZeroes(nums []int) {
    slow := 0
    for fast, v := range nums {
        if v != 0 {
            nums[slow], nums[fast] = nums[fast], nums[slow]
            slow++
        }
    }
}
```

进阶版("尽量减少操作次数":赋值 + 填零,没有交换开销):

```go
func moveZeroes(nums []int) {
    slow := 0
    for _, v := range nums {      // 第一遍:非零数依次搬到前面,每次只写 1 格
        if v != 0 {
            nums[slow] = v
            slow++
        }
    }
    for ; slow < len(nums); slow++ {  // 第二遍:尾巴统一填 0
        nums[slow] = 0
    }
}
```

- **学生答对关键观察**(2026-09-05):trace 结束 slow=3 ✓、slow 右边全 0 ✓、**不需要补 0** ✓ —— 理解了 swap 版精髓:交换时 0 被顺手带去 [slow,fast) 区间,零自然向右漂移,循环不变量全程自洽
- **第一版代码批改**(2026-09-05):骨架正确(swap + 墙),但有 6 处错误。**编译错误**:① `slow, fast := 0` —— `:=` 双变量要双值(其实 fast 应交给 range 管理,只声明 slow);② `nums[fast]` 裸当 if 条件 —— Go 条件必须 bool,C 的"非零即真"不适用;③ `return nums` —— 签名无返回值不能 return,原地修改靠 slice 共享底层数组。**逻辑错误**:④ 条件对象搞错:该判"扫描员手里的数",不是墙上的数;⑤ `slow++` 放在 if 外:墙必须在"放进一个非零数后"才右移;⑥ `fast++` 多余且与 range 冲突(循环内新变量遮蔽外层)
- **第二版批改**(2026-09-05):6 处错误修对 5 处(slow 声明、slow++ 入 if、删 fast++、删 return、`nums[fast] != 0` 显式比较)✓。残留:`nums[slow] == 0 &&` 仍在条件里 → 用 `[1,0,3]` 打脸:fast=0 时 nums[slow]=1≠0,整条条件短路为假,slow 永远停在 0,输出 `[1,0,3]` ✗(期望 `[1,3,0]`)。根因:墙上是谁不重要(slow 只是坑位),扫描员手里的数才是唯一裁判 → 教训:**一个变量一个职责,条件里别让"坑"参与"货"的判断**。另:`for fast, _ := range` 的 `,_` 可省略写成 `for fast := range`
- **第三版批改 = 通关**(2026-09-05):正确可 AC ✓。学生保留内层 `if nums[slow]==0` 防御检查——**多余但无害**:由循环不变量,slow<fast 时墙下必是 0(检查白做);slow==fast 时是自交换(等于没做)。真正必要的只有"手里的数非零"这一判 → 教学点:不变量证明过的事,代码里不用再查一遍
- **进阶讲解**(2026-09-05):交换版一个循环、零自然右漂;赋值+填零版非零覆写(1 写/个)+ 尾部填 0(1 写/格),无交换开销、写次数固定 n —— 这就是"尽量减少操作次数"的方向。两者同为 O(n) 时间 / O(1) 空间
