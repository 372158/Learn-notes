# 11. 盛最多水的容器 (Container With Most Water)

> 难度:中等 | 分类:双指针

## 题目描述

给定一个长度为 `n` 的整数数组 `height` 。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])` 。

找出其中的两条线，使得它们与 `x` 轴共同构成的容器可以容纳最多的水。

返回容器可以储存的最大水量。

**说明：**你不能倾斜容器。

 

**示例 1：**

![示意图](https://aliyun-lc-upload.oss-cn-hangzhou.aliyuncs.com/aliyun-lc-upload/uploads/2018/07/25/question_11.jpg)

```
输入：[1,8,6,2,5,4,8,3,7]
输出：49 
解释：图中垂直线代表输入数组 [1,8,6,2,5,4,8,3,7]。在此情况下，容器能够容纳水（表示为蓝色部分）的最大值为 49。
```

**示例 2：**

```
输入：height = [1,1]
输出：1
```

 

**提示：**

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`

## 本课知识点(2026-09-06)

**1. 对撞指针**(学生 day 4 自创、本题转正):left 从头、right 从尾出发,初始宽最大;每轮**淘汰矮板**向中间收,直到相遇。O(n) 时间 / O(1) 空间。

**2. 淘汰矮板为什么安全**(本题灵魂证明):矮板参与的水面恒被它自己压制,而当前组合已给它最大宽 → 它的未来全部 ≤ 当前值(已记账),退休;高板还有"遇到更高搭档"的未来,保留。

**3. 双指针铁律**:更新账本(ans)和挪指针是**两件独立的事**;循环每一轮必须让世界前进一点,挪指针无条件执行,否则死循环。

**4. 公式锚定**:写代码前把定义抄下来(水量 = 下标差 × min(两板)),每一版代码对着定义验收——本题三稿翻车全部源于公式脱离定义凭感觉改。

**5. trace 是第一调试工具**:死循环、错误公式,手数两三步全都能抓;但 trace 本身也要验算(本课 2×2=2 的手算滑坡)。

**Go 积累**:`min(a, b)` 新版内置,老版自己写 helper;`if` 条件不加括号;`left, right := 0, len(x)-1` 双声明;gofmt:`} else {`。

## 我的代码

第三版(通关版,学生独立写出,含自写的 min 辅助函数):

```go
func min(x, y int) int {
    if x < y {
        return x
    }
    return y
}

func maxArea(height []int) int {
    left := 0
    right := len(height) - 1
    ans := min(height[left], height[right]) * (right - left)
    if right-left == 1 {
        return ans
    }
    for left < right {
        area := (right - left) * min(height[left], height[right])
        if area > ans {
            ans = area
        }
        if height[left] < height[right] {
            left++
        } else {
            right--
        }
    }
    return ans
}
```

简化版(去掉冗余的种子和早退,循环全覆盖):

```go
func maxArea(height []int) int {
    left, right := 0, len(height)-1
    ans := 0
    for left < right {
        area := (right - left) * min(height[left], height[right])
        if area > ans {
            ans = area
        }
        if height[left] < height[right] {
            left++
        } else {
            right--
        }
    }
    return ans
}
```

- **学生作答**(2026-09-06):① 暴力复杂度不会算(第三次卡壳)→ 用具体两层循环结构手数:外层 n × 内层平均 n/2 = n²/2,与 day 1/day 3 暴力的 n²/2 同源;n=10⁵ 时 ≈5×10⁹,1 秒法则判超时;② 对撞"淘汰矮板"直觉正确 ✓,但"为什么矮板永远不用再考虑"讲不出 → 论证:矮板参与的水面恒被它压制,而当前组合已给足它最大宽 → 含矮板的未来容器 ⊆ 更窄×同高 ≤ 当前值,已记账,退休安全;高板未来仍可遇更高搭档,保留
- **第一版代码批改**(2026-09-06):骨架全对(left/right/ans/循环条件/挪矮侧判断),两处硬伤:① 面积公式错两处——漏 min(两板)(水面由短板决定,不能默认 left 矮)+ 宽多加 1(宽 = right-left;反例 [1,1]:正确 1,公式得 2);② 挪指针被 `if ans < m` 嵌套 → 面积不创新高时无人挪动 → **死循环**(反例 [2,1,2])。教学点:更新 ans 与挪指针是两件独立的事,**挪指针必须每轮无条件执行**。另:`}else {` 不合 gofmt。待修复重交 + 补 trace 表
- **第二版批改**(2026-09-06):死循环消失 ✓(if/else 两分支都会动指针)。但三处跑偏:① 面积公式 `height[left+1] * (right-left+1)` 既无 min、也对不上任何真实容器((left+1,right) 的宽应为 right-left-1);② 决策规则从"**谁矮谁挪**"变成"刷新纪录→挪 left,否则挪 right",与两板高度无关,反例 `[1,2,4,3]`:正确答案 4,该代码得 12;③ ans 用错误公式播种(`height[left]` 非 min),其实 `ans := 0` 让循环自己算第一对即可。**根因诊断:连续两版未做 trace,凭感觉发明公式** → 处方:给出三行伪代码骨架(算面积→记账→无条件挪矮侧),要求先按正确公式 trace `[1,2,4,3]` 三行再交代码
- **第三版批改 = 通关**(2026-09-06):代码正确可 AC ✓ —— 按定义算面积(min 这次没缺席)、记账、无条件挪矮侧,还自写了 min 辅助函数,标准对撞指针。小瑕疵:① trace 第二行 2×2 手算成 2,把 ans=4 弄丢(代码对、手算错 → **trace 也要验算**);② ans 种子 + n==2 早退是冗余(循环全覆盖,可删但无害);③ `if (...)` 带括号非 Go 惯例
