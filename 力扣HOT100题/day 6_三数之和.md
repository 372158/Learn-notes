# 15. 三数之和 (3Sum)

> 难度:中等 | 分类:双指针
> 来源:[力扣 HOT 100 - Day 6](https://leetcode.cn/problems/3sum/description/?envType=study-plan-v2&envId=top-100-liked)
> 状态:🚧 进行中(2026-09-07)

## 题目描述

给你一个整数数组 `nums` ，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k` 且 `j != k` ，同时还满足 `nums[i] + nums[j] + nums[k] == 0` 。请你返回所有和为 `0` 且不重复的三元组。

**注意：**答案中不可以包含重复的三元组。

 

 

**示例 1：**

```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
解释：
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0 。
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0 。
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0 。
不同的三元组是 [-1,0,1] 和 [-1,-1,2] 。
注意，输出的顺序和三元组的顺序并不重要。
```

**示例 2：**

```
输入：nums = [0,1,1]
输出：[]
解释：唯一可能的三元组和不为 0 。
```

**示例 3：**

```
输入：nums = [0,0,0]
输出：[[0,0,0]]
解释：唯一可能的三元组和为 0 。
```

 

**提示：**

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## 我的思路

<!-- 先自己想,把想法写在这里;卡住了向老师要提示 -->

**(2026-09-07,师生共建)** 三步走:

1. **排序** —— 让相同的数肩并肩(Day 2 的 sort.Slice),也是对撞指针的前提;
2. **固定一个,降维打击** —— 遍历 i 固定 nums[i],移项得剩下两数需满足 `x + y = -nums[i]`,在有序区间 [i+1, n-1] 上对撞(Day 5):和太小 left++ 换大数,和太大 right-- 换小数;
3. **去重** —— 排序让相同值相邻,"看一眼邻居"即可:外层 `nums[i]==nums[i-1]` 跳整轮;内层记账挪动后 left/right 各自跳过与前驱/后继相同的值。

暴力三层循环 O(n³),n=3000 时 ≈2.7×10¹⁰,超 1 秒法则 270 倍 → 排序 O(n log n) + n 轮 × 对撞 n 步 = **O(n²)**。

## 我的代码(第一版,Go,2026-09-07,一次通过)

```go
import "sort"

func threeSum(nums []int) [][]int {
    sort.Slice(nums, func(i, j int) bool { return nums[i] < nums[j] }) // 先排序

    res := [][]int{}
    for i := 0; i < len(nums)-2; i++ { // i 最多到 n-3,给 left/right 留位
        if i > 0 && nums[i] == nums[i-1] { // 外层去重:与前一个相同,整轮跳过
            continue
        }
        left, right := i+1, len(nums)-1
        for left < right {
            sum := nums[i] + nums[left] + nums[right]
            if sum == 0 {
                res = append(res, []int{nums[i], nums[left], nums[right]})
                left++ // 先走出这对组合
                right--
                for left < right && nums[left] == nums[left-1] { // 内层去重:跳 left 重复值
                    left++
                }
                for left < right && nums[right] == nums[right+1] { // 内层去重:跳 right 重复值
                    right--
                }
            } else if sum < 0 {
                left++ // 和太小 → 换大数
            } else {
                right-- // 和太大 → 换小数
            }
        }
    }
    return res
}
```

**第一版代码批改 = 通关**:逻辑全对,一次通过 —— 外层去重、内层去重、记账后先挪再跳、left 从 i+1 出发,四个易错点全部正确。风格 5 处 nit(不影响 AC):① `bool {return...}` 大括号后缺空格(**与 Day 2 同款,第二次出现,要长肌肉记忆**);② `{continue}` 同上;③ `i + 1 ,` 逗号前不能有空格;④ 两个去重 for 缩进比上面对齐少一格;⑤ `nums[i]+ nums[left]` 加号两边空格不一致。

## 复杂度分析

- **时间复杂度:** O(n²) —— 排序 O(n log n) + 外层 n-2 轮 × 每轮对撞最多 n-i-1 步。
- **空间复杂度:** O(log n) 排序递归栈(不计输出)。

对比暴力 O(n³)=2.7×10¹⁰:这就是"固定一个数,三维降二维"的降维打击。

## 关键知识点

1. **降维思想**:三数之和 = 枚举一个数 + 两数之和(Day 1 的老朋友)。面试常见的四数之和就是再套一层:枚举两个数 + 对撞,O(n³)。
2. **去重的前提是排序**:相同值相邻,才使得"只和邻居比"就够。两处去重位置:外层在轮次开头(和前一个比),内层在记账 left++/right-- 之后(和前一个/后一个比)。
3. **为什么外层跳过第二个 -1 不会漏解**:[-1,-1,2] 由第一个 -1 那轮找到 —— left 从 i+1 出发,天然覆盖后面的第二个 -1。跳过的不是"值",是"重复的探索空间"。
4. **剪枝(可选)**:排序后若 nums[i] > 0 可直接 break —— 三个正数之和必为正。

## 总结

本题三个锚句:

1. **排序是去重和双指针的共同前提** —— 不排序,两者都无从谈起;
2. **固定一个数,三维降二维** —— n³ 变 n² 的钥匙;
3. **去重 = 同一个值在同一个岗位上只探索一次** —— 排序让相同的数相邻,"看一眼邻居"就够。

Day 4/5/6 双指针三部曲收官:移动零(快慢指针)→ 盛水(对撞)→ 三数之和(排序+对撞+去重)。Day 7 接雨水是对撞指针的巅峰一战。
